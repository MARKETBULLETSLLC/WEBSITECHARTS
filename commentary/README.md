# MarketBullets — Commentary Pipeline

One plain-text file per commentary session, saved into this folder.
The watcher indexes and pushes it; the website renders it — current for
members, 10-trading-day delayed for the public landing page — from the
same file. No Squarespace edits, ever.

---

## Writing in Word (updates the Members Dashboard)

1. Open `_TEMPLATE.docx` (or yesterday's file) and write. While drafting, keep a
   name that starts with `_` — e.g. `_DRAFT_2026-10-23.docx` — so Word's AutoSave
   never publishes half a sentence.
2. When it's ready: **File → Save a Copy** into this folder as `YYYY-MM-DD.docx`.
3. Done. `tools/word_commentary.py` waits until the file stops changing (45 s),
   then writes `YYYY-MM-DD.md`, rebuilds `index.json`, rewrites `MB_CONFIG` in the
   dashboard (dateline, bullets, body, and Box-o-Rox status / prices if filled in),
   commits, and pushes. marketbulletsllc.com/market-bullet_points shows it on the
   next page load, usually within a couple of minutes.

To fix a typo after publishing: open `YYYY-MM-DD.docx`, fix, save. Same path.

| In Word | On the dashboard |
|---|---|
| `Dateline:` line at top | Dateline. Leave blank for the automatic `FRIDAY, OCTOBER 23, 2026 · Pre-Dawn Update` |
| `Box-o-Rox: SUSPEND / EXECUTE / TRIPWIRE` | BoR badge. Add `· Oct 22, 2026` to set the date, otherwise the previous weekday |
| Prices table (Contract, Open, High, Low, Close, Chg) | Closing prices. Rows left blank are left unchanged; delete the table to skip prices |
| First paragraph (Title style) | Headline |
| Word bullet list | Bullets. Start one with `[bull]` `[bear]` `[global]` `[usda]` `[macro]` to color it |
| Paragraphs after the bullets | Narrative. Bold, italics, hyperlinks carry over; bullets here become a list |
| `[chart: WHEAT_SRW_D \| caption]` | Chart thumbnail (opens in the lightbox) |

Only the newest dated `.docx` drives the dashboard; re-saving an older one just
refreshes its `.md`. The page header in the template has a cheat sheet and is
never published.

Run it: double-click `start_word_watcher.bat`, or run
`tools/install_word_watcher_task.ps1` once to start it silently at every login.
Log: `tools/word_commentary.log`.

## Daily workflow (Gary)

1. Write the commentary in any text editor.
2. Save it into this folder as `YYYY-MM-DD.md` (the session date), e.g. `2026-07-12.md`.
3. Done. `commentary_watcher.py` detects the file, rebuilds `index.json`,
   commits, and pushes. The member page shows it within ~5 minutes.

To correct a published commentary: edit the same file and re-save.
The watcher pushes the update automatically.

## File format

```
# HEADLINE GOES HERE

- First bullet of the briefing. One or two sentences.
- Second bullet.
- As many bullets as the session needs.

---

Full narrative starts after the three-dash line. Write normal
paragraphs separated by blank lines.

[chart: WHEAT_SRW_D | SRW daily — third close below the 60-day]

Paragraphs continue after a chart. Place chart tags on their own
line wherever the chart belongs in the read.

Plain links work markdown-style: [July WASDE](https://www.usda.gov/oce/commodity/wasde) —
they render as normal hyperlinks.
```

### Rules

| Element | Rule |
|---|---|
| **Filename** | `YYYY-MM-DD.md` — the date controls ordering and the 10-day delay. Files starting with `_` are ignored (templates, samples, drafts). |
| **Headline** | First non-empty line. Leading `#` optional — it is stripped. |
| **Bullets** | Lines starting with `-` before the `---` separator. |
| **Separator** | A line containing only `---` divides briefing from narrative. |
| **Narrative** | Everything after `---`. Blank lines separate paragraphs. |
| **Chart tag** | `[chart: FILENAME]` or `[chart: FILENAME | caption]` on its own line. FILENAME is the chart's generic name **without** `.png` (e.g. `WHEAT_SRW_D`). |
| **Links** | `[link text](https://url)` anywhere in bullets or narrative. |

### How chart tags render

The same tag serves both audiences:

- **Member page** → thumbnail from `charts/FILENAME.png` (current), click opens lightbox
- **Landing page** → thumbnail from `charts/10daydelay/FILENAMEOLD.png` (10-trading-day-old version, matching the delayed commentary date)

So a chart referenced in delayed commentary always shows the chart *as it
looked when that commentary was written*. Never reference a chart that
isn't in `charts/` under its permanent generic filename.

## What the site reads

`index.json` (regenerated by the watcher on every save):

```json
{
  "generated": "2026-07-12T21:40:00",
  "entries": [
    { "date": "2026-07-12", "headline": "HEADLINE", "file": "2026-07-12.md" }
  ]
}
```

- **Member commentary block** — fetches `index.json`, shows the newest entry,
  "Read more" opens the full dated index.
- **Landing commentary block** — same fetch, but shows the newest entry dated
  ≤ 10 trading days ago (same trading-day calendar as `tools/delay_updater.py`),
  and "Read more" is a subscribe CTA.

Raw URLs:

```
https://raw.githubusercontent.com/marketbulletsllc/WEBSITECHARTS/main/commentary/index.json
https://raw.githubusercontent.com/marketbulletsllc/WEBSITECHARTS/main/commentary/YYYY-MM-DD.md
```

## Running the watcher

Same pattern as the chart watcher:

```
python tools/commentary_watcher.py            # watch mode (leave running)
python tools/commentary_watcher.py --once     # single pass: index, commit, push, exit
```

Or double-click `start_commentary_watcher.bat` in the repo root.
To auto-start at login: Win+R → `shell:startup` → paste a shortcut to the .bat.
